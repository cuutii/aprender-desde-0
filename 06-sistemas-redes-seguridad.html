Sistemas, redes y seguridad

Los cimientos que sostienen todo lo demás: cómo funcionan Windows y Linux, cómo se habla con la terminal (CMD, PowerShell, Bash), qué es programar, cómo viajan los datos por la red y cómo se protegen. De cero, sin asumir nada.

Para quién es: para quien quiere entender cómo funciona una computadora por dentro y por fuera, antes de programar o de defenderse en ciberseguridad.

Cómo está escrito: cada idea usa el mismo molde — Teoría (qué es), Ejemplo (una analogía cotidiana), Qué hace, Cómo lo hace y Cómo se ejecuta (el código real). Al final de cada capítulo, una práctica.

Capítulo 1Windows: el sistema operativo

Windows es el traductor entre vos y el hardware. Sin él, la PC es un montón de metal mudo.

¿Qué es un sistema operativo?

TeoríaEl sistema operativo (SO) es el programa que gestiona el hardware y permite que otros programas (apps) funcionen. Es el intermediario entre el usuario y la máquina: tú le pedís "abrir un archivo" y él se encarga de hablar con el disco, la memoria y la pantalla.
EjemploEs el director de orquesta: vos (el público) pedís una canción, y él coordina a los músicos (CPU, memoria, disco, pantalla) para que suene. Sin director, cada músico toca lo que quiere y es ruido.
Qué haceGestiona recursos (CPU, memoria, disco, dispositivos) y provee una interfaz (ventanas, consola) para que uses la máquina.
Cómo lo haceCon un kernel (el núcleo que habla con el hardware) y un espacio de usuario (donde corren las apps). Windows usa el kernel NT (desde Windows NT, 1993).
Cómo se ejecutaPara ver tu SO: Win+R → winver → Enter. Ahí ves la versión exacta de Windows y el build.

Sistema de archivos (NTFS) y rutas

TeoríaWindows organiza los datos en archivos y carpetas dentro de unidades (C:, D:). El sistema de archivos por defecto es NTFS, que soporta permisos, cifrado (EFS), compresión y archivos grandes (>4 GB). Las rutas usan barra invertida: C:\Users\Juan\documento.txt.
EjemploEs como un archivador con cajones: la unidad C: es el archivador, las carpetas son los cajones, y los archivos son las fichas. La ruta es la dirección exacta para encontrar una ficha: "archivador C, cajón Users, subcajón Juan, ficha documento.txt".
Qué haceGuardar, organizar y proteger los datos en el disco.
Cómo lo haceCon una tabla maestra de archivos (MFT) que registra cada archivo, su ubicación en el disco, sus permisos y sus metadatos. NTFS también lleva un journal (registro de cambios) para recuperarse de cortes de luz.
Cómo se ejecutaPara ver el sistema de archivos de un disco: Win+R → diskmgmt.msc → Enter. Para ver la letra y el tipo de sistema de archivos: Win+R → cmd → fsutil fsinfo ntfsinfo C:.

El Registro de Windows

TeoríaEl Registro es una base de datos jerárquica donde Windows guarda toda su configuración: hardware, software, usuarios, preferencias. Se organiza en claves (como carpetas) y valores (como archivos). Las claves raíz son: HKLM (máquina local), HKCU (usuario actual), HKCR (clases), HKU (usuarios), HKCC (configuración actual).
EjemploEs como el manual de instrucciones del edificio: cada apartamento (clave) tiene sus reglas (valores). Si alguien modifica el manual (el Registro), el edificio cambia de comportamiento — por eso el malware suele modificarlo para autoarrancar.
Qué haceCentralizar la configuración del sistema y las aplicaciones.
Cómo lo haceCon archivos binarios (hive) en C:\Windows\System32\config\ y en el perfil del usuario (NTUSER.DAT). Se cargan en memoria al arrancar.
Cómo se ejecutaPara abrir el editor del Registro: Win+R → regedit → Enter. Ojo: modificar el Registro puede romper el sistema. Siempre exportá una copia antes (Archivo → Exportar).

Usuarios, grupos y permisos (NTFS)

TeoríaWindows tiene usuarios (cuentas individuales) y grupos (conjuntos de usuarios con los mismos permisos). Los permisos NTFS controlan qué puede hacer cada usuario con cada archivo/carpeta: lectura, escritura, modificación, ejecución, control total. El principio de mínimo privilegio: cada usuario tiene solo los permisos que necesita.
EjemploEs como las llaves de un edificio: el portero (administrador) tiene la llave maestra; los inquilinos (usuarios estándar) tienen la llave de su departamento; los visitantes (invitados) solo pueden entrar al lobby. Si le das la llave maestra a todos, cualquiera puede entrar a cualquier lado.
Qué haceControlar quién puede hacer qué con cada recurso.
Cómo lo haceCon listas de control de acceso (ACL) en cada archivo/carpeta, que registran qué usuario o grupo tiene qué permiso.
Cómo se ejecutaPara ver/editar permisos: clic derecho en un archivo/carpeta → Propiedades → pestaña Seguridad. Para crear un usuario: Win+R → lusrmgr.msc → Enter (solo en Pro/Enterprise).

Procesos y servicios

TeoríaUn proceso es un programa en ejecución (cada app que abrís es un proceso). Un servicio es un proceso que corre en segundo plano, sin interfaz visible, y suele arrancar con el sistema. El Administrador de tareas (taskmgr) muestra los procesos; services.msc muestra los servicios.
EjemploLos procesos son los empleados trabajando (cada uno en su escritorio). Los servicios son los sistemas del edificio (calefacción, seguridad) que funcionan solos, sin que nadie los vigile.
Qué haceEjecutar programas y mantener servicios del sistema funcionando.
Cómo lo haceWindows asigna a cada proceso un PID (identificador único), memoria y recursos. Los servicios se registran en el Registro y se inician por el Service Control Manager (SCM).
Cómo se ejecutaPara ver procesos: Ctrl+Shift+Esc (Administrador de tareas) → pestaña Procesos. Para ver servicios: Win+R → services.msc → Enter. Para ver desde consola: tasklist (CMD) o Get-Process (PowerShell).

Capítulo 2Linux: el sistema operativo libre

Linux es el sistema operativo que corre en el 90 % de los servidores del mundo, en tu router, en tu TV y en tu celular (Android). Es libre, gratuito y abierto.

¿Qué es Linux?

TeoríaLinux es un kernel (núcleo) de sistema operativo libre creado por Linus Torvalds en 1991. Lo que llamamos "Linux" en la práctica es una distribución (distro): el kernel + herramientas (GNU) + un gestor de paquetes + un entorno de escritorio. Ejemplos: Ubuntu, Debian, Fedora, Arch, Kali, Mint.
EjemploEl kernel es el motor del auto; la distribución es el auto completo (motor + carrocería + radio + ruedas). Podés cambiar la carrocería (el entorno de escritorio) sin cambiar el motor.
Qué haceProveer un sistema operativo libre, estable y seguro para servidores, escritorios y dispositivos embebidos.
Cómo lo haceCon un kernel monolítico (todo en un solo programa) que gestiona hardware, procesos, memoria y sistema de archivos. Las distros agregan las herramientas de usuario.
Cómo se ejecutaPara ver tu distro y kernel: cat /etc/os-release y uname -r. Para instalar software: sudo apt install paquete (Debian/Ubuntu) o sudo dnf install paquete (Fedora).

Sistema de archivos (FHS) y rutas

TeoríaLinux organiza todo en un único árbol que arranca en / (raíz). No hay letras de unidad (C:, D:). Todo es un archivo: discos, dispositivos, procesos. El estándar FHS (Filesystem Hierarchy Standard) define dónde va cada cosa: /home (usuarios), /etc (configuración), /var (datos variables), /tmp (temporales), /usr (programas), /bin (binarios esenciales).
EjemploEs como un árbol genealógico invertido: la raíz / es el abuelo, y de él cuelgan todos los demás. No hay "cajones separados" (unidades C:, D:): todo cuelga del mismo árbol. Tu casa (/home/tuusuario) es una rama de ese árbol.
Qué haceOrganizar todo el sistema en una estructura única y predecible.
Cómo lo haceCon un sistema de archivos (ext4, btrfs, xfs) y puntos de montaje: cada disco o partición se "monta" en una carpeta del árbol.
Cómo se ejecutaPara ver el árbol: ls /. Para ver dónde estás: pwd. Para navegar: cd /home/tuusuario. Para ver el espacio en disco: df -h.

Permisos (rwx) y usuarios

TeoríaEn Linux cada archivo tiene 3 tipos de permiso para 3 tipos de usuario: r (read/leer), w (write/escribir), x (execute/ejecutar), para el dueño, el grupo y otros. Se ven como -rwxr-xr-x (9 letras). El dueño suele ser el usuario que creó el archivo; el grupo es un conjunto de usuarios; "otros" es todo el mundo.
EjemploEs como las llaves de una casa: el dueño (rwx) puede entrar, modificar y dar permiso; el grupo (r-x) puede entrar y mirar pero no cambiar nada; los demás (r--) solo pueden mirar desde la ventana. Si le das rwx a todos, cualquiera puede entrar y romper todo.
Qué haceControlar quién puede leer, modificar o ejecutar cada archivo.
Cómo lo haceCon un número de 12 bits por archivo (modo, dueño, grupo) guardado en los metadatos del sistema de archivos (inodo).
Cómo se ejecutaPara ver permisos: ls -l archivo. Para cambiar: chmod 755 archivo (rwxr-xr-x) o chmod +x archivo (agregar ejecución). Para cambiar dueño: sudo chown usuario:grupo archivo. Para ver tu usuario: whoami y id.

sudo y root

Teoríaroot es el superusuario de Linux (UID 0): puede hacer todo, sin restricciones. sudo permite a un usuario normal ejecutar un comando como root, pidiendo su propia contraseña. El principio de mínimo privilegio: trabajá como usuario normal y usá sudo solo cuando haga falta.
EjemploEs como el portero del edificio: root es el dueño del edificio (puede abrir cualquier puerta); vos sos un inquilino (solo tu departamento). sudo es pedirle al portero que abra una puerta por vos, mostrando tu DNI.
Qué hacePermite ejecutar comandos privilegiados sin loguearse como root.
Cómo lo haceCon el archivo /etc/sudoers que define qué usuarios pueden usar sudo y para qué comandos. Se edita con visudo (nunca a mano).
Cómo se ejecutaPara instalar algo: sudo apt install paquete. Para editar un archivo del sistema: sudo nano /etc/hosts. Para ver quién sos: whoami (sin sudo) vs sudo whoami (root).

Procesos y servicios

TeoríaEn Linux todo es un proceso. Cada programa en ejecución tiene un PID (identificador único). Los servicios (daemons) corren en segundo plano, gestionados por systemd (el init system moderno). Los comandos clave: ps, top, htop, systemctl.
EjemploLos procesos son los empleados trabajando (cada uno con su número de legajo = PID). Los servicios son los sistemas del edificio (calefacción, seguridad) que funcionan solos. systemd es el gerente que los arranca y los para.
Qué haceEjecutar programas y mantener servicios del sistema funcionando.
Cómo lo haceCon el kernel (que gestiona CPU, memoria, I/O) y systemd (que gestiona el arranque y los servicios). Cada proceso tiene su propio espacio de memoria.
Cómo se ejecutaPara ver procesos: ps aux o top. Para ver un servicio: systemctl status ssh. Para arrancar/parar: sudo systemctl start/stop/restart ssh. Para habilitar al arranque: sudo systemctl enable ssh.

Capítulo 3CMD: la consola clásica de Windows

CMD (Command Prompt) es la consola original de Windows, heredada de MS-DOS. Sigue viva y es útil para tareas rápidas.

¿Qué es CMD?

TeoríaCMD (cmd.exe) es el intérprete de comandos de Windows, heredado de MS-DOS (1981). Ejecuta comandos y scripts batch (.bat/.cmd). Es más limitado que PowerShell: trabaja con texto plano, no con objetos. Pero sigue siendo útil para tareas rápidas y compatibilidad.
EjemploEs como el teléfono de disco: viejo, simple, hace lo básico. PowerShell es el smartphone. Pero el teléfono de disco sigue funcionando y a veces es lo único que tenés a mano.
Qué haceEjecutar comandos y scripts de automatización simples en Windows.
Cómo lo haceInterpretando línea por línea los comandos que le pasás, y ejecutando los programas externos que le indicás.
Cómo se ejecutaPara abrir: Win+R → cmd → Enter. Para ejecutar como administrador: clic derecho en el ícono → "Ejecutar como administrador".

Comandos esenciales de CMD

TeoríaLos comandos más usados en CMD para navegar, listar, crear, copiar, mover y borrar archivos y carpetas.
EjemploEs como el vocabulario básico para hablar con la computadora: con 15 palabras ya podés hacer el 90 % de las tareas diarias.
Qué haceTe permite operar el sistema desde la consola.
Cómo lo haceCada comando es un programa (interno o externo) que CMD invoca con los argumentos que le pasás.
Cómo se ejecutaProbá estos en orden: 
# Navegación
cd C:\Users\TuNombre\Desktop   # cambiar de carpeta
dir                             # listar archivos
cd ..                           # subir un nivel
cd \                            # ir a la raíz

# Crear / borrar
mkdir mi_carpeta                # crear carpeta
echo hola > archivo.txt         # crear archivo con texto
type archivo.txt                # ver contenido
copy archivo.txt copia.txt      # copiar
move copia.txt mi_carpeta\      # mover
del mi_carpeta\copia.txt        # borrar
rmdir mi_carpeta                # borrar carpeta vacía

# Red y sistema
ipconfig                        # ver IP
ping google.com                 # probar conexión
tasklist                        # ver procesos
systeminfo                      # info del sistema

Scripts batch (.bat)

TeoríaUn script batch es un archivo de texto con comandos CMD, uno por línea, que se ejecuta automáticamente. La extensión es .bat o .cmd. Se usan para automatizar tareas repetitivas en Windows.
EjemploEs como una receta de cocina: escribís los pasos una vez y después solo la ejecutás. En vez de tipear 10 comandos cada mañana, los guardás en un .bat y lo corrés con un doble clic.
Qué haceAutomatizar tareas repetitivas en Windows.
Cómo lo haceCMD lee el archivo línea por línea y ejecuta cada comando. Podés usar variables (%variable%), condicionales (if), bucles (for) y pausas (pause).
Cómo se ejecuta1) Abrí el Bloc de notas. 2) Escribí los comandos. 3) Guardá como mi_script.bat (no .txt). 4) Doble clic para ejecutar. Ejemplo: 
@echo off
rem Este script crea una carpeta y un archivo
mkdir mi_proyecto
cd mi_proyecto
echo Hola mundo > readme.txt
type readme.txt
pause
CMD vs PowerShell
CMD trabaja con texto. PowerShell trabaja con objetos. PowerShell es más potente y es el presente/futuro de Windows. CMD sigue existiendo por compatibilidad. Si vas a aprender uno solo, aprendé PowerShell.

Capítulo 4PowerShell: la consola moderna de Windows

PowerShell no es "CMD con esteroides": es un lenguaje de scripting completo que trabaja con objetos, no con texto.

¿Qué es PowerShell?

TeoríaPowerShell es un shell y lenguaje de scripting de Microsoft, creado en 2006 (Monad). Es orientado a objetos: cada comando devuelve objetos .NET, no texto. Es cross-platform (Windows, macOS, Linux) desde PowerShell Core (2016). Es el estándar de administración de Windows.
EjemploEs como el paso de texto a planilla de cálculo: CMD te da texto suelto que tenés que parsear; PowerShell te da objetos con propiedades que podés filtrar, ordenar y encadenar. Como pasar de una carta manuscrita a una base de datos.
Qué haceAutomatizar tareas de administración y configuración en Windows (y ahora en Linux/macOS).
Cómo lo haceCon cmdlets (comandos .NET que siguen el patrón Verbo-Sustantivo, ej. Get-Process, Set-Location), un pipeline (encadenar comandos con |), y un lenguaje de scripting completo (variables, funciones, condicionales, bucles).
Cómo se ejecutaPara abrir: Win+R → pwsh (PowerShell 7) o powershell (Windows PowerShell 5.1) → Enter. O buscá "PowerShell" en el menú inicio.

Cmdlets esenciales

TeoríaLos cmdlets siguen el patrón Verbo-Sustantivo: Get-Process, Set-Location, New-Item, Remove-Item. Los verbos comunes: Get (obtener), Set (configurar), New (crear), Remove (borrar), Start (iniciar), Stop (detener).
EjemploEs como el vocabulario de un idioma: con 20 verbos y 20 sustantivos podés armar cientos de frases. Get-ChildItem = "obtener elementos hijos" = listar archivos. Set-Location = "establecer ubicación" = cambiar de carpeta.
Qué haceEjecutar operaciones sobre el sistema y los datos.
Cómo lo haceCada cmdlet es una clase .NET que procesa entrada y produce salida (objetos) que se pueden encadenar con |.
Cómo se ejecutaProbá estos: 
# Navegación y archivos
Get-Location                          # dónde estoy (pwd)
Set-Location C:\Users\TuNombre\Desktop # cambiar carpeta (cd)
Get-ChildItem                         # listar (ls/dir)
New-Item -ItemType Directory -Name mi_carpeta   # crear carpeta (mkdir)
New-Item -ItemType File -Name archivo.txt       # crear archivo
Get-Content archivo.txt              # ver contenido (cat/type)
Copy-Item archivo.txt copia.txt       # copiar (cp/copy)
Move-Item copia.txt mi_carpeta\      # mover (mv/move)
Remove-Item mi_carpeta\copia.txt     # borrar (rm/del)

# Sistema
Get-Process                          # ver procesos (ps/tasklist)
Get-Service                          # ver servicios
Get-ComputerInfo                     # info del sistema
Test-Connection google.com           # ping
Get-NetIPAddress                     # ver IP

El pipeline (|): el superpoder

TeoríaEl pipeline (|) pasa la salida de un comando como entrada del siguiente. La diferencia con CMD/bash: en PowerShell se pasan objetos, no texto. Eso permite filtrar, ordenar y transformar sin parsear texto.
EjemploEs como una cadena de montaje: cada estación recibe un objeto, lo modifica y lo pasa a la siguiente. En CMD/bash, cada estación recibe texto y tiene que "adivinar" qué es. En PowerShell, cada estación sabe exactamente qué propiedades tiene el objeto.
Qué haceEncadena comandos para filtrar, ordenar y transformar datos.
Cómo lo hacePasando objetos .NET de un cmdlet a otro. Los cmdlets intermedios (Where-Object, Select-Object, Sort-Object) filtran y transforman.
Cómo se ejecutaEjemplos: 
# Procesos que usan más de 100 MB de RAM, ordenados
Get-Process | Where-Object { $_.WorkingSet64 -gt 100MB } | Sort-Object WorkingSet64 -Descending | Select-Object -First 5 Name, WorkingSet64

# Servicios detenidos
Get-Service | Where-Object { $_.Status -eq "Stopped" } | Select-Object Name, Status

# Archivos .txt modificados en los últimos 7 días
Get-ChildItem -Recurse -Filter *.txt | Where-Object { $_.LastWriteTime -gt (Get-Date).AddDays(-7) } | Select-Object Name, LastWriteTime

Scripting en PowerShell (.ps1)

TeoríaLos scripts de PowerShell tienen extensión .ps1. El lenguaje incluye variables ($variable), condicionales (if/else), bucles (for/foreach/while), funciones, manejo de errores (try/catch) y clases. La política de ejecución (ExecutionPolicy) controla si se pueden ejecutar scripts (por defecto está restringida).
EjemploEs como el batch de CMD pero con superpoderes: en vez de texto suelto, trabajás con objetos, funciones reutilizables y manejo de errores estructurado. Es el lenguaje de automatización de Windows.
Qué haceAutomatizar tareas complejas de administración.
Cómo lo haceCon un lenguaje completo basado en .NET, con cmdlets, funciones y módulos reutilizables.
Cómo se ejecuta1) Creá un archivo script.ps1. 2) Escribí el código. 3) Verificá la política: Get-ExecutionPolicy. 4) Si está en "Restricted", cambiala: Set-ExecutionPolicy RemoteSigned -Scope CurrentUser. 5) Ejecutá: .\script.ps1. 
# Ejemplo de script PowerShell
param([string]$Nombre = "mundo")

function Saludar {
    param([string]$Quien)
    Write-Host "Hola, $Quien!" -ForegroundColor Green
}

Saludar -Quien $Nombre

# Bucle con condicional
for ($i = 1; $i -le 5; $i++) {
    if ($i -eq 3) { Write-Host "Tres!" -ForegroundColor Yellow }
    else { Write-Host "Número $i" }
}
Políticas de ejecución
Restricted (por defecto): no ejecuta scripts. RemoteSigned: ejecuta scripts locales, los descargados deben estar firmados. Unrestricted: ejecuta todo (peligroso). Bypass: ignora la política (solo para pruebas). Recomendación: usá RemoteSigned para tu usuario.

Capítulo 5Bash: la shell de Linux y macOS

Bash (Bourne Again Shell) es la shell por defecto en la mayoría de las distribuciones de Linux y en macOS. Es el lenguaje de automatización del mundo Unix.

¿Qué es Bash?

TeoríaBash es un intérprete de comandos y lenguaje de scripting para sistemas Unix/Linux, creado en 1989 por Brian Fox para el proyecto GNU. Es un superset del Bourne shell (sh): todo lo que funciona en sh funciona en Bash. Es el estándar de facto en Linux.
EjemploEs como el idioma común del mundo Linux: si sabés Bash, podés hablar con cualquier servidor Linux del planeta. Como el inglés en los aeropuertos: no es el único idioma, pero es el que todos entienden.
Qué haceInterpretar comandos y ejecutar scripts de automatización en sistemas Unix/Linux.
Cómo lo haceLeyendo línea por línea, tokenizando (separando por espacios y metacaracteres), expandiendo variables y ejecutando comandos externos o builtins.
Cómo se ejecutaPara abrir: en Linux/macOS, abrí la terminal (Ctrl+Alt+T en Ubuntu). En Windows: instalá WSL (Windows Subsystem for Linux) o Git Bash. Para ver tu shell: echo $SHELL. Para ver la versión: bash --version.

Comandos esenciales de Bash

TeoríaLos comandos más usados en Bash para navegar, listar, crear, copiar, mover, borrar, buscar y gestionar procesos.
EjemploEs el vocabulario básico de cualquier administrador de sistemas Linux. Con 20 comandos ya podés operar un servidor.
Qué haceTe permite operar el sistema desde la terminal.
Cómo lo haceCada comando es un programa (builtin o externo en /bin, /usr/bin) que Bash invoca con los argumentos que le pasás.
Cómo se ejecutaProbá estos: 
# Navegación y archivos
pwd                              # dónde estoy
cd /home/tuusuario               # cambiar carpeta
ls -la                           # listar (incluyendo ocultos)
mkdir mi_carpeta                 # crear carpeta
echo "hola" > archivo.txt        # crear archivo con texto
cat archivo.txt                  # ver contenido
cp archivo.txt copia.txt         # copiar
mv copia.txt mi_carpeta/         # mover
rm mi_carpeta/copia.txt          # borrar archivo
rm -r mi_carpeta                 # borrar carpeta y contenido

# Búsqueda
grep "texto" archivo.txt         # buscar texto en archivo
find /home -name "*.txt"         # buscar archivos por nombre

# Procesos y sistema
ps aux                           # ver procesos
top                              # monitor en vivo
kill 1234                        # matar proceso por PID
df -h                            # espacio en disco
free -h                          # memoria RAM
uname -a                         # info del sistema

Variables y scripting en Bash

TeoríaLas variables en Bash se asignan con nombre=valor (sin espacios) y se leen con $nombre o ${nombre}. Los scripts tienen extensión .sh y empiezan con shebang (#!/bin/bash o #!/usr/bin/env bash). Bash soporta variables, arrays, condicionales, bucles, funciones y redirección de entrada/salida.
EjemploEs como una receta de cocina escrita en un idioma que la cocina (el sistema) entiende. El shebang (#!/bin/bash) le dice al sistema "usá Bash para leer esto". Sin shebang, el sistema no sabe qué intérprete usar.
Qué haceAutomatizar tareas en Linux/macOS.
Cómo lo haceCon un lenguaje completo basado en el Bourne shell, con expansión de variables, control de flujo y redirección.
Cómo se ejecuta1) Creá un archivo script.sh. 2) Primera línea: #!/bin/bash. 3) Escribí los comandos. 4) Dale permiso de ejecución: chmod +x script.sh. 5) Ejecutá: ./script.sh. 
#!/bin/bash
# Script de ejemplo

nombre="mundo"
echo "Hola, $nombre!"

# Condicionales
if [ "$nombre" = "mundo" ]; then
    echo "Es el mundo"
else
    echo "No es el mundo"
fi

# Bucle for
for i in 1 2 3 4 5; do
    echo "Número $i"
done

# Función
saludar() {
    echo "Hola, $1!"
}
saludar "Juan"

Capítulo 6Programación: los fundamentos

Programar no es escribir código: es resolver problemas con instrucciones ordenadas. El código viene después.

Variables y tipos de datos

TeoríaUna variable es un nombre que guarda un valor. Los tipos de datos básicos son: entero (int, sin decimales), decimal (float/double, con decimales), texto (string, cadenas de caracteres), booleano (true/false) y carácter (char, una sola letra).
EjemploEs como las cajas etiquetadas de un depósito: la caja "edad" guarda el número 25, la caja "nombre" guarda el texto "Juan", la caja "activo" guarda true o false. El tipo de dato es el tamaño y forma de la caja: no podés meter un texto en una caja de números.
Qué haceGuardar información para usarla después.
Cómo lo haceReservando espacio en memoria y asociándole un nombre y un tipo.
Cómo se ejecutaEn Python: edad = 25, nombre = "Juan", activo = True. En C/Java: int edad = 25;, String nombre = "Juan";. El tipo puede ser explícito (C/Java) o inferido (Python/JS).

Control de flujo: condicionales y bucles

TeoríaLos condicionales (if/else, switch) eligen un camino según una condición. Los bucles (for, while) repiten un bloque. Juntos permiten que el programa tome decisiones y repita acciones.
EjemploEl condicional es el semáforo: si está en verde, avanzás; si está en rojo, parás. El bucle es el metrónomo: repite el mismo movimiento una y otra vez hasta que le digás "pará".
Qué haceControlan qué se ejecuta y cuántas veces.
Cómo lo haceEvaluando condiciones (true/false) y repitiendo bloques mientras la condición se cumpla.
Cómo se ejecutaEn Python: 
if edad >= 18:
    print("Mayor de edad")
else:
    print("Menor de edad")

for i in range(5):
    print(i)   # 0,1,2,3,4

while contador < 10:
    contador += 1

Funciones

TeoríaUna función es un bloque de código reutilizable que recibe parámetros y puede devolver un valor. Permite no repetir código y organizar el programa en piezas lógicas.
EjemploEs el botón del microondas: apretás "descongelar" y ejecuta una rutina entera guardada. No tenés que decirle paso por paso cada vez; solo apretás el botón.
Qué haceReusar y ordenar el código.
Cómo lo haceDefiniendo un bloque con nombre y parámetros, y llamándolo cuando se necesita. La función void ejecuta sin devolver nada; la que declara un tipo devuelve con return.
Cómo se ejecutaEn Python: def saludar(nombre): return f"Hola, {nombre}" → saludar("Juan") devuelve "Hola, Juan". En C/Java: int sumar(int a, int b) { return a + b; }.

POO: clases y objetos

TeoríaLa programación orientada a objetos (POO) organiza el código en clases (moldes) y objetos (cosas hechas con ese molde). Los atributos son las propiedades, los métodos los comportamientos. Sus 4 pilares: encapsulamiento, herencia, abstracción y polimorfismo.
EjemploLa clase Persona es el molde de cédula: define que toda persona tiene nombre, altura y año de nacimiento. Tus datos y los míos son dos objetos distintos hechos con el mismo molde — mismas variables, valores distintos.
Qué haceModelar el mundo real en software de forma ordenada y reutilizable.
Cómo lo haceCon clases que definen atributos y métodos, y objetos que son instancias de esas clases. La herencia permite que una clase hija reutilice lo de la padre.
Cómo se ejecutaEn Python: class Persona: def __init__(self, nombre): self.nombre = nombre → juan = Persona("Juan") → juan.nombre devuelve "Juan". En Java: public class Persona { private String nombre; public Persona(String n) { nombre = n; } }.

Paradigmas de programación

TeoríaUn paradigma es una forma de pensar y estructurar el código. Los principales: imperativo (paso a paso: C, Python), orientado a objetos (clases y objetos: Java, C++), funcional (funciones puras, sin estado: Haskell, Lisp), declarativo (describís qué querés, no cómo: SQL, HTML).
EjemploEs como cocinar: imperativo = "cortá la cebolla, calentá el aceite, agregá la cebolla" (paso a paso). Declarativo = "quiero una sopa de cebolla" (describís el resultado). Funcional = "transformá estos ingredientes con estas funciones" (sin modificar los originales).
Qué haceDar distintas formas de resolver problemas.
Cómo lo haceCada paradigma impone restricciones y estilo distintos. La mayoría de los lenguajes modernos son multiparadigma (Python, JS, C#).
Cómo se ejecutaNo se "ejecuta": se elige. Para empezar, aprendé un lenguaje imperativo + POO (Python o Java). El paradigma funcional y declarativo se aprenden después, naturalmente.

Capítulo 7Redes: cómo viajan los datos

Una red es computadoras que se hablan. El secreto está en las capas y en los protocolos.

El modelo OSI (7 capas)

TeoríaEl modelo OSI divide la comunicación en 7 capas, de la más física (cable, capa 1) a la más abstracta (aplicación, capa 7). Cada capa hace un trabajo y se comunica solo con sus vecinas.
EjemploEs como el correo postal: escribís una carta (capa 7), la metés en un sobre (capa 6), la pasás al correo (capa 4), tiene dirección y ruta (capa 3), va en un camión con patente (capa 2), el camión rueda por la ruta (capa 1).
Qué haceDa un lenguaje común para hablar de redes y de dónde entra cada ataque.
Cómo lo haceCada capa le agrega a los datos un encabezado (encapsulación). Al llegar, el receptor lo quita capa por capa (desencapsulación).
Cómo se ejecutaPara ver el camino de un paquete: tracert google.com (Windows) o traceroute google.com (Linux). Para ver tu IP: ipconfig (Windows) o ifconfig/ip a (Linux).
CapaNombreEjemplo real
7AplicaciónNavegador, correo, DNS
6PresentaciónCifrado, compresión, imágenes
5SesiónAbrir y mantener la conversación
4TransporteTCP (confiable) y UDP (rápido)
3RedIP, enrutamiento, ARP
2EnlaceMAC, switches, Wi-Fi
1FísicaCable, fibra, radio

TCP/IP y DNS

TeoríaTCP/IP es el conjunto de protocolos que hace funcionar Internet. TCP (capa 4) garantiza que los datos lleguen completos y en orden. IP (capa 3) direcciona los paquetes. DNS traduce nombres (google.com) a IPs (142.250.185.46). HTTP/HTTPS (capa 7) es el protocolo de la web.
EjemploEs como el servicio de correo: TCP es el cartero que garantiza que la carta llegue (y pide confirmación); IP es la dirección postal; DNS es la guía telefónica que traduce "la casa de Juan" a "Calle Falsa 123". HTTP es el idioma en que se escriben las cartas.
Qué hacePermite que millones de computadoras se comuniquen de forma ordenada.
Cómo lo haceCon paquetes que llevan dirección de origen y destino, confirmación de recepción (TCP), y resolución de nombres (DNS).
Cómo se ejecutaPara traducir un nombre: nslookup google.com o ping google.com. Para ver las conexiones activas: netstat -an. Para ver la IP pública: curl ifconfig.me.

IP, puertos y subnetting básico

TeoríaUna IP (v4) es un número de 32 bits (4 octetos, ej. 192.168.0.34). Se divide en red y host según la máscara de subred (ej. /24 = 255.255.255.0 = 256 IPs, 254 usables). Los puertos (0-65535) identifican el servicio dentro de la IP. Los conocidos (0-1023): HTTP=80, HTTPS=443, SSH=22, DNS=53, FTP=21.
EjemploLa IP es la dirección del edificio; el puerto es el número de departamento. La máscara de subred es el código postal: define qué parte de la dirección es el barrio (red) y cuál es la casa (host). Subnetting es dividir un barrio en manzanas más chicas para organizar mejor.
Qué haceDireccionar y organizar el tráfico de red.
Cómo lo haceCon direccionamiento IP (capa 3) y puertos (capa 4), organizados en subredes.
Cómo se ejecutaPara ver tu IP y máscara: ipconfig (Windows) o ip a (Linux). Para calcular subredes: usá una calculadora online (ej. subnet-calculator.com) o el comando ipcalc 192.168.0.0/24 en Linux.
IPv6
IPv4 se está agotando (solo 4.300 millones de direcciones). IPv6 usa 128 bits (ej. 2001:0db8:85a3::8a2e:0370:7334) y tiene direcciones prácticamente infinitas. La transición es gradual; hoy conviven ambos (dual stack).

Capítulo 8Seguridad informática: los fundamentos

Seguridad no es "hackear": es proteger tres cosas que todas las organizaciones necesitan.

La triada CIA

TeoríaLa ciberseguridad protege sistemas, redes y datos. Su marco central es la triada CIA: confidencialidad (solo quien debe ver, ve), integridad (nadie altera sin permiso) y disponibilidad (funciona cuando se necesita).
EjemploPensá en una cámara de seguridad con llave: solo la gente autorizada tiene la llave (confidencialidad), nadie puede borrar las grabaciones (integridad) y la cámara tiene que estar prendida (disponibilidad). Si falla una, el sistema entero falla.
Qué haceProtege información (no solo equipos).
Cómo lo haceAplicando controles en tres frentes: personas (capacitación, contraseñas), procesos (permisos, respaldos, auditorías) y tecnología (cifrado, firewalls, antivirus).
Cómo se ejecutaAnte cada dato, preguntá: 1) ¿Quién lo puede ver? 2) ¿Puede alguien modificarlo sin que nadie se dé cuenta? 3) ¿Está disponible cuando hace falta? Si la respuesta a alguna es "no sé", hay trabajo pendiente.

Amenazas y vulnerabilidades

TeoríaUna vulnerabilidad es un fallo accidental (de diseño, configuración o implementación). Una amenaza es la acción que la aprovecha. El exploit es el código que la materializa. "Las vulnerabilidades nunca son deliberadas." Las amenazas comunes: ransomware, phishing, inyección SQL, DoS/DDoS, malware.
EjemploLa ventana abierta es la vulnerabilidad (nadie la dejó a propósito). La escalera es el exploit. El ladrón que la usa es la amenaza. Podés quitar la escalera, pero si la ventana sigue abierta…
Qué haceEl exploit convierte un fallo en un hecho: acceso, roto, caído.
Cómo lo haceExplotando la superficie de ataque: hardware, software, sistema operativo y la persona (la capa más blanda).
Cómo se ejecutaPara saber si ya existe exploit para un fallo: 1) Buscá el número CVE en nvd.nist.gov. 2) Consultá exploit-db.com. 3) Anotá si ya hay parche: sin parche, el riesgo es urgente.

Criptografía básica

TeoríaLa criptografía protege la información. Hash: huella única e irreversible (MD5, SHA256) — para integridad y contraseñas. Cifrado simétrico: misma clave para cifrar y descifrar (AES). Cifrado asimétrico: par de claves (pública cifra, privada descifra) — RSA, HTTPS. Firma digital: prueba quién envió y que no se modificó.
EjemploCifrar es escribir una carta en un idioma que nadie habla (el cartero la ve pero no entiende). El hash es la huella dactilar del archivo: si alguien lo modifica, la huella cambia. La firma digital es el sello de cera: prueba quién la envió.
Qué haceConfidencialidad (que solo el destinatario lea) e integridad (que nadie la altere).
Cómo lo haceCon algoritmos matemáticos que transforman datos legibles en datos ilegibles sin la clave correcta.
Cómo se ejecutaPara generar un hash: echo -n "texto" | sha256sum (Linux) o Get-FileHash archivo.txt (PowerShell). Para cifrar: gpg -c archivo.txt. Para ver certificados HTTPS: clic en el candado del navegador.

Autenticación y autorización

TeoríaAutenticación = verificar quién sos (login, contraseña, MFA). Autorización = qué podés hacer (permisos, roles). Son distintas. El MFA combina algo que sabés (contraseña) + algo que tenés (teléfono) + algo que sos (huella).
EjemploEs como entrar a un club: autenticación es mostrar tu DNI en la puerta. Autorización es que el portero te diga "podés entrar al salón VIP porque sos socio". MFA es mostrar DNI + tarjeta de socio + huella.
Qué haceControlar quién entra y qué puede hacer.
Cómo lo haceCon sistemas de identidad (Active Directory, LDAP), tokens (JWT, OAuth) y políticas de acceso (RBAC, ABAC).
Cómo se ejecutaPara activar MFA en Google/Microsoft: Configuración → Seguridad → Verificación en dos pasos. Para ver tus permisos en Windows: whoami /groups. En Linux: sudo -l.

Defensa en profundidad

TeoríaLa defensa en profundidad usa múltiples capas de seguridad: si una falla, la siguiente frena al atacante. Capas: firewall (perímetro), IDS/IPS (detección), antivirus/EDR (endpoint), cifrado (datos), backups (recuperación), capacitación (personas). Ninguna capa sola es suficiente.
EjemploEs como las murallas de un castillo: foso, muralla externa, muralla interna, torreón. Si el enemigo cruza el foso, todavía tiene 3 murallas más. Y si entra, el tesoro está en una caja fuerte (cifrado) con backup en otro castillo.
Qué haceGarantizar que un solo fallo no comprometa todo.
Cómo lo haceCon capas independientes que se refuerzan mutuamente.
Cómo se ejecutaChecklist: 1) Firewall activo. 2) Antivirus/EDR actualizado. 3) Contraseñas fuertes + MFA. 4) Respaldos automáticos (3-2-1). 5) SO actualizado. 6) No abrir archivos de desconocidos.
Regla de oro
La seguridad no es un producto, es un proceso. No se "instala" una vez y se olvida. El eslabón más débil siempre es la persona.

Capítulo 9Cierre y recursos

Recorriste sistemas, redes y seguridad. Ahora tenés el mapa completo.

Resumen en 6 ideas

1Un sistema operativo es el traductor entre vos y el hardware. Windows (NTFS, Registro, ACL) y Linux (FHS, permisos rwx, sudo, systemd) son los dos grandes.
2CMD trabaja con texto; PowerShell con objetos (cmdlets, pipeline, .ps1). Bash es el estándar de Linux/macOS (comandos, scripts .sh, shebang).
3Programar es resolver problemas con instrucciones ordenadas: variables, tipos, control de flujo, funciones, POO, paradigmas.
4Las redes se organizan en capas (OSI). TCP/IP direcciona y transporta; DNS traduce nombres; HTTP/HTTPS es la web. IP + puertos + subnetting.
5La seguridad protege confidencialidad, integridad y disponibilidad (triada CIA). Amenazas + vulnerabilidades + exploits. Criptografía (hash, simétrico, asimétrico). Autenticación ≠ autorización. Defensa en profundidad.
6El eslabón más débil siempre es la persona. La seguridad es un proceso, no un producto.
